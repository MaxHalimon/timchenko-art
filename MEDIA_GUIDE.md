# Медіа: як усе влаштовано і що робити

Картини продаються як **фізичні полотна**, тому покупцю ніколи не віддається файл.
Звідси схема:

| Що | Де лежить | Хто бачить |
|---|---|---|
| `thumb-<hash>.webp` (≤900px, водяний знак) | публічний бакет R2 | всі (картки, каруселі, стрічка галереї) |
| `large-<hash>.webp` (≤2000px, водяний знак) | публічний бакет R2 | всі (сторінка картини, повноекранний перегляд) |
| `original-<hash>.jpg` (повний розмір) | **приватний** бакет R2 | тільки ви (для друку/архіву) |
| `hero-loop-<hash>.mp4` | публічний бакет R2 | всі |
| `hero-poster.jpg` (80 КБ) | репозиторій | всі — щоб кадр з'являвся миттєво |

У БД лежать **відносні ключі** (`paintings/<slug>/large-ab12cd34.webp`). Повний URL
складається в `lib/media.ts` з `S3_PREVIEWS_PUBLIC_URL`. Тому перехід з `r2.dev` на
власний домен — це зміна однієї змінної, без міграцій даних.
Хеш у назві файлу = кешування «назавжди» + автоматичне оновлення після заміни картини.

## Одноразова міграція (по порядку)

1. `npm install` (додано `sharp`).
2. Перенесіть оригінали з `public/paintings/` у `media-src/paintings/`, відео —
   в `media-src/hero-loop.mp4` (папка в `.gitignore`).
3. Заповніть `.env` (`S3_*`, включно з `S3_PREVIEWS_PUBLIC_URL`) **і ті самі змінні на Vercel**.
4. `npx prisma migrate deploy` — додає колонку `thumbImageKey` (нічого не ламає).
5. `npm run media:upload` — генерує WebP з водяним знаком, вантажить у R2, пише `lib/media-manifest.json`.
6. `npx prisma db seed` — записує ключі в БД (сид тепер справді працює з R2).
7. `npm run media:verify` — робить HEAD-запит на кожен файл; покаже, якщо щось не віддається.
8. Закомітьте `lib/media-manifest.json`, задеплойте.
9. Коли сайт працює на нових ключах: `npm run media:cleanup` (покаже старі сирі файли в
   публічному бакеті), потім `npm run media:cleanup -- --yes` (видалить).
10. Приберіть важке з git:
    `git rm -r --cached public/paintings public/videos/hero-loop.mp4`
    (локальні копії видаліть, оригінали вже в `media-src/`). Історія git збереже старі
    35 МБ; якщо потрібно зменшити й `.git`, — `git filter-repo --path public/paintings --path public/videos/hero-loop.mp4 --invert-paths`.

Безпечний порядок: поки БД містить старі значення (`/paintings/x.jpg` або повний URL),
сайт їх так само відображає — код сумісний зі старим форматом.

## Чому раніше картини «зникали» (знайдений баг)

У `prisma/seed.ts` рядок `if (R2_PUBLIC_URL) continue;` стояв **перед** `upsert`. Коли R2
налаштований — сид пропускав усі картини і не змінював БД, хоча писав «готово».
БД лишалась зі шляхами `/paintings/...`; коли папку `public/paintings` прибирали —
усі зображення давали 404, і доводилось відкочуватись. Тепер сид читає manifest,
зупиняється з помилкою, якщо для картини немає зображень, і завжди пише в БД.
Також у `lib/s3.ts` вимкнено автоматичні checksum-заголовки нових версій AWS SDK,
які R2 обробляє нестабільно.

## Захист від копіювання (чесно)

Що зроблено:
- у публічний доступ потрапляють **тільки** файли з водяним знаком і обмеженою роздільністю (2000px — для перегляду добре, для друку на полотні замало);
- оригінал — у приватному бакеті, сайт його не віддає (`originalImageKey` навіть не вибирається в запитах карток);
- EXIF/GPS з публічних файлів видаляється;
- заборонено ПКМ, перетягування та довге натискання «зберегти зображення» (`ImageGuard`, `globals.css`).

Чого зробити **неможливо**: заборонити скриншот або збереження через DevTools — браузер
завжди має отримати картинку, щоб її показати. Тому головний захист — водяний знак у самому файлі.
Сила знака налаштовується в `scripts/upload-media.ts` (`WM`), потім `npm run media:upload -- --force`.

Ще варто зробити в Cloudflare (кодом не зробиш):
1. Підключити **власний домен** до публічного бакета (R2 → Settings → Custom Domains), прописати його в `S3_PREVIEWS_PUBLIC_URL`, а `r2.dev` вимкнути (r2.dev не кешується і має ліміти).
2. Увімкнути **Hotlink Protection** (Scrape Shield) або WAF-правило: блокувати запити до домену зображень, де Referer не ваш сайт.
3. За потреби — Bot Fight Mode / Rate limiting на домен зображень.

## Швидкість відео

Після винесення відео в R2 через Custom Domain воно віддається з CDN Cloudflare з підтримкою
Range-запитів, тож старт не повільніший (а трафік не витрачається з ліміту Vercel).
Постер лишився в репозиторії — перший кадр показується миттєво, ще до завантаження відео.
