# Timchenko Art — стартова структура

Домен поки що припущений як **timchenko-art.com.ua** (див. `.env.example` → `NEXT_PUBLIC_SITE_URL`) — оновіть, коли домен буде зареєстровано підтверджено.

## Що вже готово

- **Стилі — CSS Modules, один компонент = одна папка.** Кожен компонент живе у своїй підпапці разом зі своїм `ComponentName.module.css` (напр. `components/AgeGate/AgeGate.tsx` + `components/AgeGate/AgeGate.module.css`). Спільні шматки, що не належать одному компоненту, лежать окремо в `components/shared/`:
  - `shared/Buttons.module.css` — `.galleryButton` / `.galleryButtonOutline` (як у ТЗ, з hover-ефектом).
  - `shared/HeaderSelect.module.css` — спільний стиль `<select>` для `LanguageSwitcher` і `CurrencySwitcher`.
  - `shared/ProductGrid.module.css` — сітка карток, спільна для головної й галереї.
  - `globals.css` лишається тільки для CSS-змінних палітри (`--color-*`, `--font-*`, `--space-*`) і base-стилів (`body`, `h1-h4`, `img`) — жодних утилітарних класів там більше немає, все або в модулі компонента, або токен.
- Дизайн-система зафіксована як CSS-змінні в `globals.css` — колір, шрифти, spacing. Незмінна.
- **Мультимовність (next-intl):** 5 мов зараз (`uk`, `en`, `de`, `fr`, `ja`), маршрутизація через префікс (`/uk/gallery`, `/en/gallery`, `/fr/gallery`, `/ja/gallery`...). Мова за замовчуванням для структурних випадків — `uk`, а для нового відвідувача мову підбирає геолокація (`lib/geoLocale.ts`: країни без власної мови сайту отримують `en`). Додати ще одну мову — 3 кроки: код у `i18n/config.ts` → `locales`, новий `messages/<code>.json`, підпис у `LOCALE_LABELS` (а також рядок у `lib/geoLocale.ts`, якщо хочете автовибір за країною). Все інше підхоплюється автоматично. ⚠️ Лист про статус замовлення (`lib/orderEmails.ts`) теж має тексти кожною мовою — не забудьте їх додати для нової.
- **Вибір валюти:** middleware читає заголовок `x-vercel-ip-country` (Vercel виставляє його автоматично в проді) і виставляє cookie `timchenko-art-currency` з валютою за замовчуванням для країни відвідувача (включно з JPY для Японії). `CurrencySwitcher` дозволяє ручний вибір, який теж пишеться в ту саму cookie і відтоді має пріоритет над геолокацією. `PriceTag` рендерить ціну в обраній валюті.
- `AgeGate` — модалка при першому вході, стан у `localStorage`.
- **Мобільна адаптація:** хедер стає бургер-меню на екранах ≤720px (`SiteHeader.tsx`, клієнтський компонент зі станом відкриття); фільтри галереї стають вертикальними на ≤480px; `--space-4/5/6` токени в `globals.css` автоматично звужуються на ≤480px, тож усі контейнери (hero, галерея, футер) підтягуються без окремих правок.
- **Головна-маніфест (натхненна особистими сайтами Kusama/Murakami):** повноекранний блок на 100vh (100dvh на мобільних) нагорі. Зараз це **циклічне фонове відео** (`HeroVideo`, відео з R2, ключ у `lib/media-manifest.json`; лишається лише `public/videos/hero-poster.jpg`) — `muted + loop + playsInline + autoplay`, з `poster`-кадром (`hero-poster.jpg`) на час завантаження і фолбеком без автовідтворення для `prefers-reduced-motion`. Оригінальне відео важило 103 МБ у 4K — стиснуто через `ffmpeg` до ~3 МБ (1280×720, без звукової доріжки, `crf 28`, `+faststart`); якщо будете оновлювати відео — не забувайте про той самий процес стиснення, інакше сторінка вантажитиметься дуже довго. Попередній варіант — слайд-шоу з картин бази (`HeroSlideshow`) — лишився в проєкті невикористаним, неважко повернути чи перемкнути.
  - На головній навігація повністю інша: `ImmersiveNav` — лише логотип + бургер-іконка поверх відео (прозорий фон із градієнтом для читабельності, стає суцільним білим після невеликого скролу), **завжди** у форматі "меню-по-кліку" незалежно від ширини екрана (на відміну від звичайного `SiteHeader`, де на десктопі меню одразу видно). `SiteHeaderSwitch` вибирає, який хедер рендерити, за поточним шляхом (`usePathname() === "/"`).
  - Одразу під відео — **`ArtistIntro`**: текстовий блок про художницю (біографія, особливості творчості, виставки, "чому варто придбати") — повний текст локалізований на всі 5 мов (`messages/*.json` → `artistIntro`).
  - Поверх відео — рукописний «маніфест» (`HeroManifestoOverlay`): курсор блимає **1 раз** → текст друкується з людською нерівномірністю → курсор блимає **2 рази** → плавно зникає. Кількість блимань — це дві константи нагорі файлу (`BLINKS_BEFORE_TYPING`, `BLINKS_AFTER_TYPING`), швидкість блимання — `BLINK_MS`; затримки рахуються з них, тож змінювати треба лише ці числа.
  - Далі — `ManifestoStatement`: коротка текстова секція з копірайтингом (`hero.eyebrow/title/description/cta`), яка раніше сиділа поверх зображення в старій `HeroSection`. `HeroSection.tsx` лишився в проєкті невикористаним.
- `BackToTop` — кнопка "нагору" внизу справа, з'являється після прокрутки ~400px, плавний скрол нагору.
- **Навігація:** пункти меню — Home / Gallery / Order Status (раніше Catalog/Process/Delivery — "Process" прибрано, "Catalog" перейменовано на "Gallery" по всьому проєкту — маршрут, назви компонентів, неймспейс перекладів `gallery.*`, посилання в UI-текстах; "Delivery" перетворилось на сторінку статусу замовлення `/tracking`, а умови доставки лишились на `/shipping-policy`). Випадне меню (і на десктопі для головної, і на мобільних для решти сторінок) — компактна картка, "прилипла" під бургер-іконкою по ширині контенту, а не повношиткова панель з великими відступами.
- **Футер із меню** — посилання на 5 юридичних сторінок (Privacy Policy, Terms of Service, Shipping Policy, Returns & Refunds, Impressum), локалізовані, з мобільним стеканням у стовпчик. Сам текст сторінок — шаблонний, дивіться `LEGAL_PAGES_GUIDE.md` у корені проєкту щодо того, що обов'язково треба заповнити/перевірити з юристом перед запуском (включно з вимогою Impressum для німецького ринку). **Дата «Востаннє оновлено» — спільна для всіх чотирьох сторінок і всіх мов і береться з однієї константи `LEGAL_LAST_UPDATED` у `lib/constants.ts` (зараз 2026-10-01); змінили будь-який юридичний текст — оновіть дату там, і більше ніде.** Строки (відправка 5 робочих днів, картина вручну 15–30 днів, повернення 14 днів, відповідь 1 робочий день) і правило повернення коштів (90% ціни) затверджені й прописані в текстах; єдиний плейсхолдер, що лишився, — `[юрисдикція]` у Terms.
- **Сторінка "Контакти" (`/contacts`)** — контактна сторінка (нав-пункт: Контакти/Contacts/Kontakt/お問い合わせ, залежно від мови). Містить: email художниці (`maryna.timchenko.art@gmail.com`, mailto-посилання), форму зворотного зв'язку на EmailJS (`ContactForm`, лист приходить напряму на пошту, без власного backend — інструкція з налаштування в `EMAILJS_GUIDE.md`), і компонент `SolidarityStatement` — заява щодо позиції студії до збройної агресії рф проти України (та інших країн). Ця сама позиція задокументована й як пункт у Terms of Service ("Обмеження щодо замовлень" — не приймаємо замовлення від клієнтів з рф) — заява на `/contacts` дає людський/ціннісний контекст, пункт у Terms — це вже операційне правило.
  - Свідомий вибір розміщення: не на головній (щоб не порушувати суто візуальне занурення першого екрана з референсів Kusama/Murakami) і не на сторінці доставки (яка суто транзакційна) — саме "Контакти" природно поєднує "хто ми" і "як з нами зв'язатись".
- `ProductCard`, `FilterBar`, галерея, юридичні сторінки — усі тексти локалізовані через `useTranslations`/`getTranslations`.
- `prisma/schema.prisma` — `users` (ADMIN/ARTIST), `products`, `orders` + `order_items` (state machine PREVIEW → PAID → PAINTING → DRYING → READY_TO_SHIP → SHIPPED → DELIVERED; одне замовлення може містити кілька картин із «Мольберта»), `payments` (STRIPE/NOWPAYMENTS/Cryptomus/Monobank), `progress_photos`.
- `lib/constants.ts` — платформна комісія зафіксована як глобальна константа 20% (`PLATFORM_COMMISSION_PCT`) — ваш заробіток; решта 80% (`calculateArtistPayoutEur`) залишається художниці. **Гроші від клієнтів надходять напряму на акаунти художниці (Stripe у Німеччині, крипто-акаунт), автоматичного розподілу немає: свої 20% ви отримуєте від неї раз на місяць за рахунком за послуги.** Схема, налаштування Stripe/PayPal/крипти й податкові орієнтири — у `PAYMENTS_GUIDE.md`; звіт для рахунку — `GET /api/admin/commission-report` (14-денне вікно повернення — `RETURN_WINDOW_DAYS`).
- `app/api/orders/route.ts` — створює `Order` (статус `PREVIEW`), приймає `locale` для локалізованих success/cancel URL, розгалужується за `paymentMethod`:
  - `"card"` (за замовчуванням) → Stripe Checkout Session **без** `payment_method_types`: набір способів оплати (картка, Apple Pay, Google Pay, PayPal) керується в Stripe Dashboard → Payment methods, а не кодом.
  - `"crypto"` → NOWPayments invoice, як опція, яку клієнт обирає сам.
  - В обох випадках — rollback замовлення, якщо запит до гейтвею впав.
- **Сторінка після оплати** (`app/[locale]/order/[id]/success`) — сюди Stripe і NOWPayments повертають клієнта (`success_url` в `app/api/orders/route.ts`): подяка, номер замовлення, кнопка на `/tracking?ref=<id>`; компонент `ClearEasel` очищає Мольберт саме тут (а не при натисканні «Оформити», щоб при скасуванні оплати вибране не зникло). Сторінку не індексують.
- **Статус замовлення для клієнта** (`/tracking`, `TrackingForm`, `POST /api/orders/track`) — пошук за номером замовлення або трек-номером; віддає лише неособисті поля (без імені, пошти, адреси). Листи клієнту про кожен статус — `lib/orderEmails.ts` через Resend (див. `ORDER_EMAILS_GUIDE.md`); змінювати статус можна тимчасовим захищеним ендпоінтом `POST /api/admin/orders/[id]/status` (потрібен `ADMIN_API_SECRET`), доки немає адмінки.
- **Медіа** — картини й відео лежать у Cloudflare R2, а не в git; повний процес — у `MEDIA_GUIDE.md` (`npm run media:upload`, `media:verify`).
- `app/api/webhooks/stripe/route.ts` і `.../nowpayments/route.ts` — перевірка підпису, ідемпотентний перехід `Order → PAID` (+ розрахунок комісії, `paidAt`) і `Product → SOLD`. Stripe-вебхук чекає на реальне підтвердження: для відкладених способів оплати (`payment_status: unpaid`) замовлення стає PAID лише після `checkout.session.async_payment_succeeded`. Підписати ендпоінт треба на 4 події — список у `.env.example`.
- `prisma/seed.ts` + `prisma/paintings.json` — заповнення галереї вашими реальними картинами без написання коду. Інструкція: `prisma/PAINTINGS_GUIDE.md`. Запуск: `npm run prisma:seed`.

## Наступні кроки (не зроблено ще)

1. Сторінка товару `app/[locale]/product/[slug]/page.tsx` вже є; лишається довести галерею етапів/процесу й вибір способу оплати (оформлення зараз іде через Мольберт → `POST /api/orders`).
2. **Сторінка "Про художницю"** (`/about`) — таймлайн кар'єри, фото зі студії, відео-інтерв'ю. Наступний крок у переосмисленні структури під особисті сайти художників (Kusama/Murakami як референс).
3. **Розділ "Новини та виставки"** (`/news`) — хронологічна стрічка подій.
4. Адмінка `app/[locale]/admin/` з розділенням прав ADMIN/ARTIST (потрібна автентифікація — рекомендую NextAuth).
5. `lib/s3.ts` — presigned URL для оригіналу, лише коли `order.status` ∈ {PAID, PAINTING, DRYING, READY_TO_SHIP, SHIPPED, DELIVERED}.
6. Відкрити Stripe **на художницю** (Німеччина, тип «sole proprietor», виплати на її німецький рахунок) і перевірити реальний вердикт щодо контенту (art nude ≠ explicit). Те саме для крипто-акаунта NOWPayments. Деталі — `PAYMENTS_GUIDE.md`.
6a. **Impressum:** сторінка `/impressum` є, але в ній три плейсхолдери з даними художниці (ім'я, адреса, ПДВ/§19 UStG) — заповнити в `messages/*.json` → `legal.impressum` до запуску.
7. **Живі курси валют:** `EXCHANGE_RATES_FROM_EUR` у `lib/currency.ts` — статичні заглушки, база — EUR (валюта, в якій художниця задає ціни). Перед запуском підключити реальний курс (напр. exchangerate-api.com) із періодичним оновленням/кешем.
8. **Відстеження посилки (частково зроблено).** Сторінка `/tracking` показує етапи замовлення, перевізника й трек-номер з полів `Order.trackingNumber`/`trackingCarrier`. Не зроблено лише *живий* статус від служби доставки через їхнє API.
9. **Impressum для німецького ринку** — юридично обов'язкова окрема сторінка при продажу в Німеччину, наразі не створена. Деталі в `LEGAL_PAGES_GUIDE.md`.
10. **Реальний відеофайл процесу роботи** — якщо згодом захочете замінити слайд-шоу на відео (як у деяких референс-сайтів), знадобиться відеофайл від Марини + fallback на слайд-шоу для повільних з'єднань/`prefers-reduced-motion`.

Та сама картина може бути написана на замовлення кілька разів за ту саму ціну (15–30 днів + 5 робочих днів на відправку). Мішане замовлення відправляється одним відправленням, коли готові всі позиції. **Ексклюзивні картини** (`Product.exclusive`): виконані на індивідуальне замовлення (ціна обговорюється окремо, на сайт не виставляються) АБО наявні в єдиному екземплярі картини, які за домовленістю з покупцем назавжди знімаються з продажу. Вони не повторюються й не друкуються: ексклюзив можна купити один раз (поки AVAILABLE, кількість 1), після цього кнопка неактивна, а блок друку на сторінці не показується. Позначити картину ексклюзивною: `POST /api/admin/products/<slug>/exclusive` з `{"exclusive": true}` і `Authorization: Bearer <ADMIN_API_SECRET>` (до продажу або одразу після) або поле `"exclusive": true` у `prisma/paintings.json`. **Моє припущення — підтвердити:** на ексклюзивну картину не продається й друк (бо «не повторюється»). **Друк:** будь-яка не ексклюзивна картина (навіть із проданим оригіналом) — друк у розмірі оригіналу за фіксованою ціною `PRINT_PRICE_EUR` (300 €); інший розмір — ціна індивідуально через контактну форму (`/contacts?print=<slug>&custom=1`), у Мольберт не потрапляє; виготовлення `PRINT_PRODUCTION_DAYS` (5 днів) + відправка `PRINT_DISPATCH_DAYS` (5 робочих днів); комісія 20% — як і на картини; друк нестандартного розміру та роботи на індивідуальне замовлення (зокрема ексклюзивні) — як правило, без повернення. **Показ:** картка `PrintTeaser` лише на сторінці галереї, під каруселлю (без кнопки; ціни обох колонок на одному рівні внизу; «від» для оригіналів — `ORIGINALS_FROM_EUR` = 1000 €); сіра картка `PrintOffer` на сторінці картини — в самому низу інформації (після розмірів і деталей); для проданого оригіналу стає червоною «Оригінал продано — друк доступний»; для IN_PROGRESS та ексклюзивних не показується. **Мольберт:** рядок = картина + варіант (олія / друк) + кількість (олія до `MAX_OIL_QUANTITY`=10, друк до `MAX_PRINT_QUANTITY`=20; ексклюзив — лише 1); один платіж за все (Stripe — окремий рядок на кожну позицію; крипта — один рахунок на суму); хрестик видалення — у правому верхньому куті картки. Стан у `localStorage` (старий формат — список slug-ів — читається й переводиться); бейдж у шапці = сумарна кількість. **Зберігання (`OrderItem`):** `variant` ORIGINAL | REPAINT | PRINT, `quantity`, `priceEur` — ціна ЗА ОДИНИЦЮ. «Олія ×3» наявної картини = 1 ORIGINAL + 2 REPAINT; якщо готова вже продана — усі REPAINT (для клієнта це різні оригінали: «готовий» і «пишеться на замовлення»). Наявну картину отримає лише один покупець — це гарантує унікальне `reservedProductId` (лише для ORIGINAL), що замінило `@unique` на `productId`. SOLD ставиться тільки після оплати рядка ORIGINAL. Сторінка статусу показує склад замовлення; для замовлення лише з друку — коротший ланцюжок (без «сохне», адмін-ендпоінт відхиляє DRYING), листи клієнту — свої тексти. Після оновлення: `npx prisma migrate dev` (міграції `20261005120000_order_item_variants_and_quantity` і `20261005130000_product_exclusive`).

## Нюанси, ще відкриті

1. **Валюта показу ≠ валюта списання (частково вирішено).** `PriceTag` показує ціну в обраній валюті (UAH/EUR/GBP/USD/JPY), і базова валюта БД тепер EUR — так само, як і фактичне списання через Stripe/NOWPayments (`currency: "eur"`). Тобто клієнт із карткою не в євро побачить на чекауті конвертацію від свого банку — це нормально й типово для мультивалютних сайтів, окремого рішення тут поки не потрібно.
2. **Гостьове замовлення чи акаунт клієнта?** — зараз гостьовий чекаут (email/ім'я прямо в `Order`).
3. **Якщо Stripe відмовить** — план Б: CCBill/Segpay/Verotel. До "card-to-crypto" сервісів на кшталт агресивно прорекламованого NexaPay варто ставитись з обережністю.
4. **Назви й описи картин** (`Product.title`, `description`) зберігаються в `Json`-полі, окремим значенням на кожну мову (`{ uk, en, de, fr, ja }`) — переклад самого контенту галереї вже реалізований, окремих таблиць перекладів не потрібно.
