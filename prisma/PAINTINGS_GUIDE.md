# Як додати ваші картини в каталог

## 1. Заповніть `prisma/paintings.json`

Це масив об'єктів — один об'єкт на одну картину. П'ять прикладів вже є у
файлі (`amber-still-life`, `azure-reverie`, `crimson-hour`, `verdant-study`,
`twilight-figure`) — скопіюйте структуру для решти.

| Поле | Тип | Опис |
|---|---|---|
| `slug` | рядок | Унікальний ідентифікатор для URL (`/product/<slug>`). Тільки латиниця, дефіси, без пробілів. |
| `title` | об'єкт `{ uk, en, de, fr, ja }` | Назва картини, окремий переклад на кожну мову сайту (див. нюанс нижче). |
| `description` | об'єкт `{ uk, en, de, fr, ja }` | Опис, так само перекладається на кожну мову (той самий підхід і той самий фолбек, що й `title`). |
| `widthCm` / `heightCm` | число | Розміри в сантиметрах. |
| `priceUsd` | число | Ціна в USD (базова валюта в системі — див. `lib/currency.ts`). |
| `theme` | рядок (необов'язково) | **Стабільний слаг**, не перекладений текст — один із `landscape`, `portrait`, `stillLife`, `abstract` (див. нюанс нижче). Можна не вказувати. |
| `status` | `"AVAILABLE"` \| `"IN_PROGRESS"` \| `"SOLD"` | Статус картини. |
| `previewImageFile` | рядок | Ім'я файлу зображення (без шляху) — файл має лежати в `public/paintings/`. |

Приклад полів `title`/`description`:

```json
"title": {
  "uk": "Бурштинова тиша",
  "en": "Amber Silence",
  "de": "Bernsteinstille",
  "fr": "Silence ambré",
  "ja": "琥珀の静寂"
},
"description": {
  "uk": "Олія на холсті. Тепла натюрмортна композиція...",
  "en": "Oil on canvas. A warm still-life composition...",
  "de": "Öl auf Leinwand. Eine warme Stillleben-Komposition...",
  "fr": "Huile sur toile. Une composition de nature morte chaleureuse...",
  "ja": "油彩、キャンバス。琥珀とキャラメルの色調で描かれた..."
}
```

Якщо в Excel-файлі спершу буде лише одна мова (наприклад, тільки
українська) — вкажіть її під ключем `"uk"` і залиште решту незаповненими.
Сайт автоматично покаже українську версію там, де перекладу ще нема (див.
нюанс нижче) — просто пізніше довкладете решту мов у ці ж об'єкти.

## 2. Додайте файли зображень

Покладіть відповідні файли в `public/paintings/` — імена мають точно
збігатися з `previewImageFile` у JSON.

### У якому форматі краще подавати фото

| Параметр | Рекомендація | Чому |
|---|---|---|
| **Формат файлу** | JPG або WebP | Найкраще стиснення для фотографій без помітної втрати якості. PNG теж підтримується, але важчий без потреби (нема прозорості чи різких країв, які PNG виправдовували б). |
| **Співвідношення сторін** | **4:5 (вертикальне)**, напр. 1600×2000 px | І картка в каталозі, і головний банер обрізають зображення саме під 4:5 (`object-fit: cover`). Якщо фото знято в іншій пропорції — середина кадру збережеться, але краї обріжуться. Якщо хочете, щоб уся картина була видна без обрізки — фотографуйте/кадруйте одразу під 4:5. |
| **Роздільність** | Довша сторона ~1600–2000 px | Достатньо для чіткого показу на будь-якому екрані, включно з Retina/4K, і не роздуває вагу сторінки. Знімати в оригінальній роздільності камери (напр. 6000×8000) не потрібно — це зайва вага без приросту якості на екрані. |
| **Вага файлу** | До ~500 КБ на фото | Впливає на швидкість завантаження каталогу. Якщо фото важче — стисніть через [squoosh.app](https://squoosh.app) (безкоштовно, у браузері, без встановлення). |
| **Кольоровий профіль** | sRGB | Стандарт для вебу. Якщо фото знято/оброблено в Adobe RGB (типово для деяких камер і Lightroom за замовчуванням) — картина на екрані клієнта може виглядати блідішою, ніж насправді. Конвертація в sRGB — стандартна опція експорту в будь-якому фоторедакторі. |
| **Кадрування** | Картина заповнює кадр, нейтральний фон/без сторонніх предметів | Це вітринне фото товару, не художня фотографія інтер'єру — зайві елементи в кадрі відволікають. |
| **Ім'я файлу** | Латиницею, як `slug`, напр. `amber-still-life.jpg` | Windows/macOS/сервери по-різному обробляють кирилицю та пробіли в іменах файлів — латиниця й дефіси уникають цієї категорії проблем повністю. |

Одне фото на картину — цього достатньо для роботи каталогу зараз. Якщо
згодом захочете галерею з кількох ракурсів або фото етапів роботи — це вже
стосується `ProgressPhoto` в схемі й окремої функціональності сторінки
товару, яку ще не реалізовано.

## 3. Запустіть сідинг

```bash
npm run prisma:seed
```

Скрипт (`prisma/seed.ts`) виведе список доданих картин і попередить, якщо
якогось файлу зображення не вистачає. Можна запускати повторно — картини
з тим самим `slug` оновляться, а не задублюються.

## Нюанс: як перекладаються `title`, `description`, `theme`, `material`

**`title` і `description`** зберігаються в БД як об'єкт `{ uk, en, de, fr,
ja }` — резолвиться під час показу через `lib/localizedText.ts` з
фолбеком: обрана мова → українська → перший наявний переклад. Обидва
поля влаштовані однаково.

**`theme`** — інакше: це не текст на конкретній мові, а стабільний
"слаг" (службове значення), який ще й використовується для фільтра в
галереї. Перелік поточних слагів і їхні переклади лежать у
`messages/*.json` під ключем `gallery.themes` — зараз це `landscape`,
`portrait`, `stillLife`, `abstract`. Якщо потрібна нова тема — додайте
новий слаг у `paintings.json` і відповідний переклад у `gallery.themes`
кожного з 5 мовних файлів. Якщо вказати тему, якої нема в словнику,
сайт не зламається — просто покаже слаг як є, неперекладеним.

**`material`** (матеріал/техніка) зараз не бере значення з
`paintings.json` взагалі — усюди на сайті показується один і той самий
перекладений рядок `productCard.material` ("олія, полотно" /
"oil on canvas" / ...), однаковий для всіх картин. Поле `material` у
Prisma-схемі лишається (за замовчуванням "Олія, полотно"), але наразі
ніде не читається — це свідоме спрощення, бо весь поточний каталог
однаково "олія на полотні". Якщо з'являться роботи в іншій техніці
(акварель, цифра тощо) і потрібно показувати це індивідуально —
дайте знати, зробимо так само, як з `theme` (слаг + словник перекладів).

## Це тимчасово

`previewImageKey`/`originalImageKey` зараз вказують на публічний файл у
`/public/paintings/` — без watermark і без приватного доступу до оригіналу.
Це ОК для розробки й перегляду каталогу зараз, але перед реальним запуском
потрібно перенести на приватний S3 (детальніше — в кореневому `README.md`,
розділ "Наступні кроки").
