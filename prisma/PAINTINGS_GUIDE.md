# Як додати ваші картини в каталог

## 1. Заповніть `prisma/paintings.json`

Це масив об'єктів — один об'єкт на одну картину. Два приклади вже є у файлі
(`misty-morning-fields`, `quiet-harbor`) — скопіюйте структуру для решти 16+.

| Поле | Тип | Опис |
|---|---|---|
| `slug` | рядок | Унікальний ідентифікатор для URL (`/product/<slug>`). Тільки латиниця, дефіси, без пробілів. |
| `title` | рядок | Назва картини (як показується в каталозі). |
| `description` | рядок | Опис — поки що одна мова (див. нюанс нижче). |
| `widthCm` / `heightCm` | число | Розміри в сантиметрах. |
| `priceUsd` | число | Ціна в USD (базова валюта в системі — див. `lib/currency.ts`). |
| `theme` | рядок (необов'язково) | Тема для фільтра в каталозі, напр. `"пейзаж"`, `"портрет"`. Можна не вказувати. |
| `status` | `"AVAILABLE"` \| `"IN_PROGRESS"` \| `"SOLD"` | Статус картини. |
| `previewImageFile` | рядок | Ім'я файлу зображення (без шляху) — файл має лежати в `public/paintings/`. |

## 2. Додайте файли зображень

Покладіть відповідні файли в `public/paintings/` — імена мають точно
збігатися з `previewImageFile` у JSON.

### У якому форматі краще подавати фото

| Параметр | Рекомендація | Чому |
|---|---|---|
| **Формат файлу** | JPG або WebP | Найкраще стиснення для фотографій без помітної втрати якості. PNG теж підтримується, але важчий без потреби (нема прозорості чи різких країв, які PNG виправдовували б). |
| **Співвідношення сторін** | **4:5 (вертикальне)**, напр. 1600×2000 px | І картка в каталозі, і головний банер обрізають зображення саме під 4:5 (`object-fit: cover`). Якщо фото знято в іншій пропорції — середина кадру збережеться, але краї обріжуться. Якщо хочете, щоб уся картина була видна без обрізки — фотографуйте/кадруйте одразу під 4:5. |
| **Роздільність** | Довша сторона ~1600–2000 px | Достатньо для чіткого показу на будь-якому екрані, включно з Retina/4K, і не роздуває вагу сторінки. Знімати в оригінальній роздільності камери (напр. 6000×8000) не потрібно — це зайва вага без приросту якості на екрані. |
| **Вага файлу** | До ~500 КБ на фото | Впливає на швидкість завантаження каталогу. Якщо фото важче — стисніть через [squoosh.app](https://squoosh.app) (безкоштовно, у браузері, без встановлення). |
| **Кольоровий профіль** | sRGB | Стандарт для вебу. Якщо фото знято/оброблено в Adobe RGB (типово для деяких камер і Lightroom за замовчуванням) — картина на екрані клієнта може виглядати блідішою, ніж насправді. Конвертація в sRGB — стандартна опція експорту в будь-якому фоторедакторі. |
| **Кадрування** | Картина заповнює кадр, нейтральний фон/без сторонніх предметів | Це вітринне фото товару, не художня фотографія інтер'єру — зайві елементи в кадрі відволікають. |
| **Ім'я файлу** | Латиницею, як `slug`, напр. `misty-morning-fields.jpg` | Windows/macOS/сервери по-різному обробляють кирилицю та пробіли в іменах файлів — латиниця й дефіси уникають цієї категорії проблем повністю. |

Одне фото на картину — цього достатньо для роботи каталогу зараз. Якщо
згодом захочете галерею з кількох ракурсів або фото етапів роботи — це вже
стосується `ProgressPhoto` в схемі й окремої функціональності сторінки
товару, яку ще не реалізовано.

## 3. Запустіть сідинг

```bash
npm run prisma:seed
```

Скрипт (`prisma/seed.ts`) виведе список доданих картин і попередить, якщо
якогось файлу зображення не вистачає. Можна запускати повторно — картини
з тим самим `slug` оновляться, а не задублюються.

## Нюанс: одна мова опису

Зараз `title`/`description` — одне поле в БД, без перекладу на uk/en/de
(на відміну від інтерфейсу сайту, який вже мультимовний). Якщо потрібно,
щоб самі картини мали переклад назви/опису — дайте знати, потрібно буде
або окремі поля на мову, або таблиця перекладів у Prisma-схемі.

## Це тимчасово

`previewImageKey`/`originalImageKey` зараз вказують на публічний файл у
`/public/paintings/` — без watermark і без приватного доступу до оригіналу.
Це ОК для розробки й перегляду каталогу зараз, але перед реальним запуском
потрібно перенести на приватний S3 (детальніше — в кореневому `README.md`,
розділ "Наступні кроки").
