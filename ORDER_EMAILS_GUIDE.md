# Листи про статус замовлення — налаштування

Окремо від `EMAILJS_GUIDE.md` (та форма працює лише в браузері й пише
листи ХУДОЖНИЦІ). Це — серверна відправка листів КЛІЄНТАМ: підтвердження
оплати і кожна зміна статусу аж до отримання картини.

## 1. Отримати ключ Resend

1. Зареєструйтесь на https://resend.com (безкоштовний план — 100 листів/день,
   3000/місяць, цього більш ніж достатньо для старту).
2. Підтвердіть свій домен (Settings → Domains) — інакше листи підуть з
   тестової адреси Resend і частіше потраплятимуть у спам.
3. Створіть API-ключ (API Keys → Create API Key).

## 2. Заповнити `.env`

```
RESEND_API_KEY="re_..."
EMAIL_FROM="Timchenko Art <orders@your-domain.com>"
```

Без `RESEND_API_KEY` листи просто не надсилаються (у консолі буде
попередження), сайт при цьому не падає — зручно для локальної розробки.

## 3. Як це працює

- `lib/email.ts` — низькорівнева відправка (fetch до Resend API).
- `lib/orderEmails.ts` — тексти листів для кожного статусу, усіма 5 мовами
  сайту (мова визначається за тим, якою мовою клієнт оформлював замовлення
  — зберігається в `Order.locale`).
- `lib/orderStatus.ts` — єдина точка, де і статус замовлення оновлюється
  в базі, і лист надсилається. **Будь-яка майбутня зміна статусу (адмінка,
  інтеграція з перевізником тощо) має викликати функції звідси
  (`markOrderPaid` / `advanceOrderStatus`), а не оновлювати
  `prisma.order.update` напряму** — інакше лист просто не піде.

## 4. Як зараз просувати статус (поки немає адмінки)

Адмін-панелі ще не існує. Тимчасово — захищений API-ендпоінт:

```
curl -X POST https://<сайт>/api/admin/orders/<orderId>/status \
  -H "Authorization: Bearer <ADMIN_API_SECRET>" \
  -H "Content-Type: application/json" \
  -d '{"status":"PAINTING"}'
```

Статуси: `PAINTING`, `DRYING`, `READY_TO_SHIP`, `SHIPPED`, `DELIVERED`.
Для `SHIPPED` обов'язково передати ще `trackingNumber` (і бажано
`trackingCarrier`) — вони підуть у лист клієнту.

`ADMIN_API_SECRET` — будь-який довгий випадковий рядок у `.env`. Без
нього ендпоінт вимкнений (відповідає 501).

## 5. Ще не реалізовано

- Реальна адмін-панель (з логіном) замість `curl`-запитів.
- Живе підтягування статусу від перевізника (Нова Пошта / Укрпошта /
  міжнародна служба) для етапу `SHIPPED` — залежить від вибору перевізника.
- Лист-нагадування "загубили номер замовлення" (за email, без розкриття
  статусу стороннім).
