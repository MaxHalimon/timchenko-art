# Налаштування EmailJS для форми на сторінці "Контакти"

Форма зворотного зв'язку (`/hello`) відправляє листи **напряму з браузера**
клієнта через EmailJS — без потреби у власному backend-сервері для пошти.
Це означає, що листи фізично не проходять через ваш сайт/сервер: браузер
клієнта напряму звертається до EmailJS, а EmailJS вже надсилає лист на
вашу пошту через підключений вами email-сервіс (Gmail тощо).

## Крок 1 — Реєстрація та підключення пошти

1. Зареєструйтесь на [emailjs.com](https://www.emailjs.com/) (є безкоштовний план — 200 листів/місяць).
2. У дашборді: **Email Services → Add New Service** → оберіть Gmail (або інший провайдер) → авторизуйте `m.tymchenko.art@gmail.com`.
3. Скопіюйте **Service ID** (виглядає як `service_xxxxxxx`).

## Крок 2 — Створення шаблону листа

1. **Email Templates → Create New Template**.
2. У полі **To Email** шаблону вкажіть **напряму** `m.tymchenko.art@gmail.com` (це фіксоване поле в самому шаблоні, а не те, що передає форма — так гарантовано, що лист завжди йде на правильну адресу, незалежно від того, що введе відвідувач).
3. У полі **From Name** можна вписати `{{from_name}}` — підставиться ім'я з форми.
4. У полі **Reply To** вкажіть `{{reply_to}}` — тоді, натиснувши "Відповісти" на отриманому листі, ви одразу відповідаєте клієнту, а не EmailJS.
5. Тіло листа (Content) — довільне, з підстановкою `{{message}}`, напр.:
   ```
   Нове повідомлення з сайту від {{from_name}} ({{reply_to}}):

   {{message}}
   ```
6. Збережіть шаблон і скопіюйте **Template ID** (`template_xxxxxxx`).

⚠️ Імена змінних (`from_name`, `reply_to`, `message`) мають **точно** збігатися з тим, що вже прописано в коді форми (`components/ContactForm/ContactForm.tsx`) — це не довільні назви, змінювати їх у шаблоні без зміни коду не можна.

## Крок 3 — Публічний ключ

**Account → General → Public Key** — скопіюйте значення (виглядає як довгий рядок символів).

## Крок 4 — Додати три значення в `.env`

```
NEXT_PUBLIC_EMAILJS_SERVICE_ID="service_xxxxxxx"
NEXT_PUBLIC_EMAILJS_TEMPLATE_ID="template_xxxxxxx"
NEXT_PUBLIC_EMAILJS_PUBLIC_KEY="ваш_публічний_ключ"
```

Так, префікс `NEXT_PUBLIC_` означає, що ці значення потраплять у код, який виконується в браузері — це нормально й очікувано для EmailJS: публічний ключ спеціально призначений бути видимим (захист від зловживань — на боці EmailJS, через ліміти та налаштування домену в дашборді, не через приховування ключа).

## Крок 5 — На Vercel

Не забудьте додати ці ж три змінні в **Vercel → Project Settings → Environment Variables** — `.env` з вашого комп'ютера туди не потрапляє автоматично.

## Обмеження домену (рекомендовано)

У дашборді EmailJS: **Account → Security → Allowed Origins** — додайте ваш реальний домен (напр. `https://tymchenko-art.com.ua`), щоб формою не могли скористатись зі сторонніх сайтів, підставивши ваш публічний ключ.
